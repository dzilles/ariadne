# System-test database

[Main README](../../README.md)

`fixtures/android-chat.sqlite` is a ready-to-use task database for a fictional Android AI chat app. It contains **30 tasks, 64 `blocked_by` dependencies, and 66 indexed text sources**. Tasks cover chat UI and persistence, multiple LLM providers, remote MCP servers and tool execution, internet search and citations, lifecycle recovery, settings, accessibility, and release testing.

The plan has one root and a connected acyclic dependency graph. Human-readable keys `APP-001` through `APP-030` are stored as tags; actual task IDs are generated by the task module. `fixtures/android-chat-tasks.json` is the editable source plan.

| State | Tasks |
| --- | --- |
| Completed | 6 |
| Ready | 4 |
| In progress | 1 |
| Blocked | 1 |
| Draft, awaiting prerequisites | 18 |

Every task has a detailed description, acceptance criteria, tags, related tasks, a commented file reference, a fictional documentation link, and history. Started tasks have simulated usage and file observations; completed tasks have simulated outcomes and Git references. The in-progress provider task has a checkpoint reference. The blocked provider task has a concrete fixture reason.

All application progress, Git hashes, URLs, and measurements are synthetic. There is no Android source repository, live LLM, MCP connection, or internet request. Vectors use the prototype's offline token-hash demo provider.

## Use a copy

The module opens SQLite databases for writing. Work on a copy to preserve the baseline:

```sh
cp tests/system/fixtures/android-chat.sqlite /tmp/android-chat-test.sqlite

echo '{"op":"search_tasks","project_id":"android-ai-chat","tag":"mcp"}' |
  cargo run --locked -- --db /tmp/android-chat-test.sqlite

echo '{"op":"search_tasks","project_id":"android-ai-chat","text":"internet search","mode":"semantic"}' |
  cargo run --locked -- --db /tmp/android-chat-test.sqlite
```

Select an individual task using a tag such as `APP-023`, then use its returned ID for edits or history queries. Draft tasks await unfinished prerequisites. The ready task `APP-010` can be started with workflow sequence 2 and completed with sequence 3, as demonstrated in the CLI system test.

## Run or regenerate

```sh
cargo test --locked --test system

# Creates a new database; refuses to overwrite an existing path.
cargo run --locked --example seed_android_chat -- /tmp/android-chat-new.sqlite
```

The generator uses the real task APIs, records synthetic workflow/runtime/Git events, validates dependency ordering and states, and indexes all source text. With no output argument it targets the baseline fixture path and still refuses overwrite. To refresh the baseline after editing the JSON plan, generate a new file, inspect it, replace the baseline deliberately, and then run the system tests. IDs and timestamps are newly generated, so regeneration preserves the plan rather than identical database bytes.

System tests copy the baseline into temporary directories. They verify the dependency graph and task fields, regeneration through the public APIs, keyword/vector search, and a CLI workflow across orchestrator, recorder, and indexer roles. The original database remains unchanged.
